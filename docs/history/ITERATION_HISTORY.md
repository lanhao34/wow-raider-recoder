### Day 4 - 2026-03-15（问题修复与优化）

#### `26007958` - "后端进程自动退出问题" ⚠️ **关键问题**
**问题描述**：
- Node.js 后端在 Docker 容器中自动退出
- 导致 502 Bad Gateway 错误

**原因分析**：
- Node.js 在事件循环为空时自动退出
- Docker 容器重启后 dist 文件被重新编译

**修复方案**：
```javascript
// 保持进程存活
const server = app.listen(PORT, '0.0.0.0', () => {
  console.log(`Backend running on 0.0.0.0:${PORT}`);
});
const keepAlive = setInterval(() => {}, 2147483647);
```

**后续问题** `00dc4877`：
- 只修改了 `dist/index.js`（编译后文件）
- 没有修改 `src/index.ts`（源文件）
- Docker 重建后修改丢失！

**经验教训**：
- 🔴 **永远修改源文件，而不是编译产物**
- 🔴 编译产物应该从源文件自动生成
- ✅ 后续已修复源文件

## 🔴 关键问题与教训

### 1. 编译产物 vs 源文件
**问题**：修改 `dist/index.js` 而非 `src/index.ts`

**影响**：
- Docker 重建后修改丢失
- 登录功能崩溃
- 用户无法测试

**教训**：
> 🔴 **永远修改源文件，而不是编译产物**
> 
> 编译产物应该从源文件自动生成，任何手动修改都会在下次构建时丢失。

**解决方案**：
- 修改 `src/index.ts`
- 运行 `docker-compose build backend` 重新构建

---

### 2. 架构变更的代价
**问题**：从纯前端到全栈的重大变更

**影响**：
- 大量代码重写
- 数据结构变更
- 部署流程复杂化

**教训**：
> ⚠️ **早期确定架构方向**
> 
> 如果预计需要后端，应该在项目开始时就设计好，而不是后期改造。

**正面影响**：
- 数据持久化
- 跨设备同步
- 在线登录

---

### 3. 权限模型设计

### 1. 认领角色流程
**冲突**：
- 设计：用户可以认领已有角色
- 实际：流程复杂，用户困惑
- 解决：简化流程，减少选项

**教训**：功能设计前应该先做用户测试

### 2. 权限模型
**冲突**：
- 设计文档：权限绑定在角色上
- 超管权限：绑定在用户上（特例）
- 影响：逻辑不一致

**建议**：统一权限绑定模型，或明确说明超管是特例

---

### 3. 掉落数量限制
**冲突**：
- 游戏规则：史诗固定 4 件，弹性按人数
- 当前实现：无限制，团长随意录入
- 风险：可能录入错误数量

**建议**：添加掉落数量校验（可配置开关）
